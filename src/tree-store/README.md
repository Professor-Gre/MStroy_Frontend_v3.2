# TreeStore

Типизированное хранилище древовидных данных, независимое от Vue. Класс хранит элементы с полями `id` и `parent`, предоставляет методы поиска, обхода и изменения дерева.

## Особое

Уточнения поведения реализации там, где исходное задание не задаёт его явно.

### Качество входных данных

По умолчанию хранилище будет ожидать корректную структуру: уникальные идентификаторы, существующих родителей и отсутствие циклов. Допускается несколько корней; у каждого корневого элемента `parent` равен `null`. Порядок входных элементов произвольный: дочерний элемент может находиться раньше своего родителя.

Проверка структуры включается опцией конструктора `validate` (по умолчанию `false`). При включённой проверке конструктор, `setItems`, `addItem` и `updateItem` отклоняют `NaN` и бесконечные значения в числовых идентификаторах и ссылках на родителей, отсутствующих родителей, ссылки на себя и циклы. Ошибка проверки не изменяет текущее состояние хранилища. При отключённой проверке корректность этих данных обеспечивает вызывающий код; обход циклических данных не поддерживается.

Проверки дубликатов идентификаторов и обновления отсутствующего элемента выполняются всегда. Числовые и строковые идентификаторы различаются: `1` и `'1'` — разные ключи.

### Работа с элементами

- Для неизвестного идентификатора `getItem` возвращает `undefined`, методы обхода — пустой массив, а `removeItem` ничего не меняет.
- Добавление дубликата и обновление отсутствующего элемента приводят к ошибке.
- `updateItem` полностью заменяет объект по его неизменяемому `id`. Пропущенные дополнительные поля не сохраняются. При изменении `parent` собственные потомки элемента остаются связаны с ним.
- `getAll` сохраняет порядок исходного массива; добавленный элемент помещается в конец. Обновление сохраняет позицию элемента в общем списке.
- Соседние элементы сохраняют исходный порядок. Новый или перенесённый к другому родителю элемент становится последним среди его детей. Обновление без смены родителя сохраняет порядок детей.
- `getAllChildren` возвращает потомков обходом в глубину, без самого исходного элемента. `getAllParents` возвращает цепочку от самого элемента до корня включительно.
- При записи хранилище поверхностно копирует каждый объект: последующее изменение его исходных полей `id`, `parent` или `label` не затронет хранилище. Элементы предполагаются обычными объектами данных, как в JSON. Вложенные объекты остаются общими по ссылке.
- Возвращаемые массивы и поля объектов предназначены только для чтения и защищены типами `readonly` и `Readonly<T>`. Изменять данные и связи следует через методы хранилища. Глубокого копирования и замораживания нет; вложенные объекты также не следует изменять напрямую.
- Дополнительный метод `hasChildren(id)` проверяет наличие детей без создания массива; для неизвестного идентификатора возвращает `false`.

## Использование TreeStore

Класс и типы экспортируются из [index.ts](index.ts). В примере путь импорта указан относительно корня проекта.

```ts
import { TreeStore } from './src/tree-store'

const store = new TreeStore([
  { id: 1, parent: null, label: 'Айтем 1' },
  { id: 'child', parent: 1, label: 'Айтем 2' },
], { validate: true })

store.getChildren(1) // [{ id: 'child', parent: 1, label: 'Айтем 2' }]
store.updateItem({ id: 'child', parent: null, label: 'Айтем 3' })
store.removeItem(1)
```

## Обзор эффективности

O-нотация показывает, как растут затраты при увеличении объёма данных, а не время выполнения в миллисекундах. O(1) означает постоянные затраты, не зависящие от размера хранилища; O(n) — линейный рост относительно числа элементов.

Обозначения в оценках:

- `n` — общее число элементов хранилища; для конструктора и `setItems` — число элементов входного массива.
- `p` — число собственных перечисляемых полей записываемого объекта, которые копируются при записи.
- `c` — число непосредственных дочерних элементов выбранного узла.
- `k` — число элементов выбранного поддерева, включая исходный узел.
- `h` — длина просматриваемой цепочки от узла к корню.

Оценки ниже предполагают среднюю стоимость операций `Map` O(1). Для конструктора и `setItems` число полей в каждом элементе считается фиксированным; если оно растёт, нужно дополнительно учитывать копирование всех полей входных объектов.

| Операция | Временная сложность без проверки структуры |
| --- | --- |
| `getItem`, `hasChildren` | O(1). |
| `getAll` | O(n) при первом чтении после изменения, затем O(1) благодаря кешу. |
| `getChildren` | O(c): сборка массива непосредственных детей. |
| `getAllChildren` | O(k): обход выбранного поддерева; исходный узел в результат не включается. |
| `getAllParents` | O(h): обход цепочки до корня. |
| Конструктор, `setItems` | O(n): копирование элементов и построение индексов. |
| `addItem`, `updateItem` | O(p): поверхностное копирование объекта; изменение индексов не требует обхода хранилища. |
| `removeItem` | O(k): обход и удаление выбранного поддерева. |

При включённой проверке структуры конструктор и `setItems` дополнительно проверяют весь набор за O(n). Добавление и смена родителя проверяют цепочку родителей за O(h), поэтому их полная стоимость — O(p + h). Обновление без смены родителя этот обход пропускает и остаётся O(p).

Общая дополнительная память индексов и кеша `getAll` — O(n). Полученные ранее массивы не обновляются при изменении хранилища; для актуальных данных нужно вызвать метод повторно.

При пакетных изменениях лучше вызвать `getAll` один раз после всех операций: чтение полного массива после каждой мутации требует повторной сборки за O(n).
