# Проверки проекта

Все команды выполняются из корня проекта после `npm ci`.

| Команда | Назначение |
| --- | --- |
| `npm test` | Unit-тесты TreeStore, composable и компонентные тесты. |
| `npm run test:e2e` | Браузерные сценарии с настоящей AgGrid. |
| `npm run test:performance` | Отдельные замеры производительности TreeStore. |
| `npm run type-check` | Проверка типов, включая тесты и конфигурационные файлы. |
| `npm run build` | Проверка типов и production-сборка. |

## Unit- и компонентные тесты

Тесты находятся рядом с реализацией в файлах `*.spec.ts`. TreeStore проверяется в Node.js, Vue-компоненты и composable — через Vue Test Utils в jsdom. Задержка загрузки управляется таймерами Vitest, а `fetch` заменён тестовой функцией: реальные запросы и двухсекундное ожидание для этих проверок не нужны.

В компонентных тестах AgGrid заменяется заглушкой для проверки передачи данных и событий. Отображение и поведение самой библиотеки проверяются браузерными сценариями.

## Браузерные сценарии

Перед первым запуском установите Chromium для Playwright:

```sh
npx playwright install chromium
npm run test:e2e
```

Можно использовать уже установленный Google Chrome:

```sh
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

Playwright сам запускает Vite на `127.0.0.1:4173`. Проверяются загрузка, иерархия, категории, нумерация после сворачивания, клавиатурное управление, различие строковых и числовых ID, выравнивание стрелок и мобильная прокрутка.

Для проверки операций composable используется отдельная страница в `tests/e2e/fixtures`: она позволяет добавлять, переносить, удалять и заменять элементы через настоящие методы composable. Эта страница не входит в production-сборку приложения.

При падении сценария скриншот и трассировка сохраняются в `test-results/`, который исключён из Git. Сообщение об отсутствии лицензии AgGrid Enterprise ожидаемо для ознакомительного режима.

## Производительность

Файл `src/tree-store/TreeStore.bench.ts` проверяет широкое дерево, глубокую цепочку и смешанную структуру на 10 000 и 100 000 элементов. Для каждой формы выводится таблица среднего и минимального времени операций в миллисекундах.

Каждый замер выполняется 30 раз без отдельного прогрева. Подготовка свежего хранилища перед изменяющими операциями не включается в их время; создание хранилища измеряется отдельно. Для `getAll` разделены чтение без кеша и чтение из кеша. Дополнительно измеряются включённая валидация и обновление без смены родителя.

Это ориентировочные замеры, а не проверка абсолютного лимита времени: результаты зависят от окружения, нагрузки и сборки мусора. Сравнивать изменения стоит в одинаковых условиях. Бенчмарки запускаются отдельно от `npm test`.
